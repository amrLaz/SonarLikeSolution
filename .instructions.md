## 🚀 Common Workflows

**Create a new feature:**
```
1. @dev-front Design the UI component
2. @dev-back Implement the API endpoint
3. @sonar Enable SAST rules for new code
4. @devsecops Secure the endpoint (auth, validation)
5. Commit & push to GitHub
```

**Fix a bug:**
```
1. Identify: Is it frontend, backend, security, or quality gate related?
2. @dev-front (UI issues), @dev-back (API issues), @sonar (quality issues)
3. Test locally with volume mounts (hot reload)
4. Commit with clear message
```

**Security audit:**
```
1. @devsecops Scan for vulnerabilities
2. @sonar Check code quality metrics
3. @dev-back Fix security issues
4. @dev-front Update UI for security UX
```

## ✅ Best Practices

1. **Always use named agents**: @dev-front, @dev-back, @sonar, @devsecops
2. **Keep secrets out**: Use `.env.example` template, never commit `.env`
3. **Push to GitHub**: Use `git push github master` (see .agent.md)
4. **Hot reload**: Frontend uses volume mounts for instant CSS/JS updates
5. **Test first**: Run local tests before pushing
6. **Quality gates**: Check SonarQube before merging
7. **Security scans**: DevSecOps validates all changes
