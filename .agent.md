# GitHub-Only Push Agent

**Purpose**: Ensure all project code is pushed to GitHub and NEVER to Azure DevOps.

## Constraints
- Default remote is `github` (https://github.com/amrLaz/SonarLikeSolution.git)
- All pushes go to `github` remote only
- Pushes to `origin` (Azure DevOps) are BLOCKED
- All files (apps/, scripts/, etc.) are included

## Workflow
1. Make changes to the codebase (including apps/, notebooks/, src/)
2. Stage files: `git add -A`
3. Commit with clear message: `git commit -m "description"`
4. Push ONLY to GitHub: `git push github master` (or current branch)
5. NEVER use `git push origin` (Azure DevOps)

## Blocked Commands
```bash
git push origin master          # ❌ BLOCKED - goes to Azure DevOps
git push origin feature/...     # ❌ BLOCKED
git push                        # ❌ BLOCKED - default would be origin
```

## Allowed Commands
```bash
git push github master          # ✅ OK - goes to GitHub
git push github feature/...     # ✅ OK
git push -u github master       # ✅ OK - set upstream to github
```

## Git Configuration
```bash
git config push.default upstream  # Safe default
git config remote.pushDefault github  # Push to github by default
```

## Directories to Always Include
```
apps/              # Frontend & Backend (web/, api/, worker/)
scripts/           # CI/CD scripts (ci_platform_scan.py, etc.)
notebooks/         # Jupyter notebooks & Python modules
src/               # .NET source code (Beneficiaries.Api/)
infra/             # Infrastructure configs (docker/, init scripts)
.env.example       # Environment template (NO secrets)
docker-compose.yml # Container orchestration
*.ini, *.toml, *.yaml  # Config files
tests/             # Test suites
```

## What NOT to Push
- `.env` (secrets) - only `.env.example`
- `node_modules/`, `venv/`, `__pycache__/`
- `.coverage`, `*.pyc`, `build/`, `dist/`
- Docker image artifacts
- Large binary files (without Git LFS)

## Before Every Push
1. Review changes: `git status`
2. Check for secrets: `grep -r "password\|token\|secret" . --exclude-dir=.git`
3. Commit: `git add -A && git commit -m "..."`
4. Push: `git push github master`

## Important
- ALL project files (apps/, scripts/, notebooks/, src/, infra/, etc.) should be tracked
- .gitignore should be minimal (only real build artifacts, no source code)
- Never commit secrets - use `.env.example` template only
- Never bypass these constraints
- Every change must go to GitHub ONLY
